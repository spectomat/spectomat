# Design decisions

What was decided, what was rejected, and why. Check it before proposing a change. This is §8 of [the specification](../docs/specification.md): a `D<n>` id anywhere in the repo names a row here, and a `§` number names a section of the specification. Ids are stable: a row states the design as it stands, and a missing id is a retired decision.

| Id | Decision | Rejected | Why |
| --- | --- | --- | --- |
| D1 | A bash picker (`phase.sh`) decides the phase | a thin foreman agent; the session deciding from the contract | deterministic, testable, costs no tokens; a false completion is structurally impossible (D24) |
| D2 | Five phase agents (`SPECIFY`, `REVIEW-SPEC`, `PLAN`, `IMPLEMENT`, `REVIEW`); the `ARCHIVE` phase's work is `agent-archive.sh` | six agents; two agents (author / builder) | `ARCHIVE` is mechanical — gates, a marker, a commit; a script that exits non-zero on a failing gate is stronger evidence than an agent claiming the gate passed |
| D3 | The contract keeps no phase sections | per-phase stubs with a "Project overrides" list | one source per phase; an override mechanism is complexity nobody has needed |
| D4 | The `ARCHIVE` phase's log line carries the gate outcome (`gates passed`) | parsing test counts out of gate output | a script knows that `gates.sh` exited 0, not what it printed; a guess would be the adjective the Log Format forbids |
| D5 | A phase agent blocks its own slug on the third strike: it writes `blocked.md` and calls `block_slug.sh` | the picker detecting the third strike and blocking the slug | the agent knows why it failed and must write the reason; the picker stays free of mutation |
| D6 | `run_gates` runs `.spectomat/gates.sh` as a script | a restricted parser; `npm run` only | operator-authored shell in their own committed repository, at the trust level of a `package.json` script the factory already runs |
| D7 | `PLAN` also claims a plan overview with no task files | leaving it stranded | a half-finished `PLAN` phase would match no stage, and the plan would be unreachable for the life of the floor |
| D8 | The `IMPLEMENT` phase executes exactly one task per iteration, in dependency order | packing file-disjoint ready tasks into one iteration as a "wave" | a wave makes the unit of dispatch differ from the unit of work, and pays with file-disjointness analysis, packability planning, shared-tree race rules, ordered commits and concurrent fix loops. One task keeps an iteration at one commit, one log line and one revert. The cost is iterations, which are cheap and unattended |
| D9 | The contract ships with the plugin as `references/contract.md` and is never rendered into the project; the operator amends it in the `## Rules` section at the top of `.spectomat/memory.md`, which wins over the contract and every brief and which no phase writes or prunes | rendering `contract.md` onto the floor once for the operator to edit; the rules in a file of their own, `amendments.md`; a migration that regenerates an old contract from the template | a rendered copy freezes the plugin's rules at arming time, so every later fix misses every armed floor, and the operator's edits drown among rules they never wrote. One file holds everything the project tells the flow, read in full every iteration, and the operator commits it, so nothing the factory writes or prunes lands unreviewed. The cost: the operator's rules share a file with what the factory writes, kept apart by a section only the operator edits; an older floor's `contract.md` or `amendments.md` is flagged by `run` and read by nothing |
| D10 | `templates/memory.md`'s own header carries what earns a line; the contract carries only when to read and write it | the rules in both files, kept in step by hand | duplicated rules drift; every iteration reads `memory.md` in Orient anyway, so the header costs no extra read |
| D11 | Craft prose lives in the brief that uses it — gate-reading in `agents/implement.md`, "`SPECIFY` and `PLAN` skip the gates" in those two briefs | keeping it in the contract, where every phase reads it | the contract is what every phase reads in full; text no operator would ever amend is craft, not steering |
| D12 | State and the pointer prompt are two kinds of thing: `state.json` is data a script parses with `jq`, the prompt is text a model reads | one Markdown file with the state in frontmatter and the prompt in its body | one file forces every reader to parse past the other half. Apart, the state is one `jq` call and the prompt needs no parsing (D23) |
| D13 | The operator puts drafts into the inbox and names them; `command-run.sh` only moves and commits what it finds there | the plugin numbering drafts from a committed counter file | intake is the project's business, not the factory's. The floor has one entrance, and drafts are worked in plain alphabetical order of the operator's names |
| D15 | `REVIEW` is one phase per plan, run when every task is closed | a reviewer subagent per task commit, with fix rounds inside the `IMPLEMENT` phase | per-task review is work the picker cannot see: no verdict, no log line, no strike, not resumable. As a phase it is an iteration like any other; its findings become task files that get the full TDD cycle; and only a whole-plan read sees a helper written twice, orphaned code or a drifted interface. The cost is latency, bounded because the gates run on every task and each task's `From previous tasks` names the seams |
| D16 | `REVIEW-SPEC` is one phase per spec, run once between `SPECIFY` and `PLAN`, and it revises the spec in place | a self-review checklist inside the `SPECIFY` brief; an approve-or-flag reviewer that sends the spec back to `SPECIFY` | the author cannot read its own spec cold; a fresh agent with only the spec and the draft is the cheapest cold read. It fixes rather than flags because the fix is a sentence, and a `SPECIFY` round trip would rewrite the whole file. Each fix is a `revised` row in §10. One round, latched by `- Verdict: READY` in §16 |
| D17 | The picker reads `state.json.slugs` to determine each slug's phase | deriving it from floor-file checks (`- Verdict:` lines, task file existence) | the phase is an explicit field, not an inference. The state is the single source of truth for the flow's progress, which makes resume possible |
| D18 | Strike counts are stored in `state.json.slugs[slug].strikes[phase]` | counting log lines in the picker | `strike_count` is one `jq` call, strikes are observable in the state, and `log.md` is a write-only audit trail |
| D19 | `/spectomat:cancel` sets `active: false` but keeps `state.json` | full disarm, removing `state.json` | `/spectomat:run` resumes the flow from the same iteration, with all slug phases and strikes preserved |
| D21 | `ARCHIVE` dispatches through a subagent like every working verdict: `spectomat:archive` invokes `agent-archive.sh` and relays its exit code unchanged | `ARCHIVE` as a bare script call | one dispatch row shape for every working verdict. The wrapper adds no judgement: its brief forbids moving a file, running a gate, or reading a non-zero exit as success, so D2's guarantee holds — the script performs every mutation and owns its exit code |
| D22 | `phase.sh` computes `subagent` and `brief` itself and emits them in its frontmatter block (§2.1, §3.3) | a dispatch table in the pointer prompt | the mapping is a pure function of `phase`; a table restating it is a second place that can drift from `agents/*.md`'s file names, with no test catching it until a dispatch fails. The picker still only prints (§5.1 note 7) |
| D23 | The pointer prompt is generated by `pointer_prompt()` in `scripts/utils.sh` — a fixed heredoc with `PLUGIN_ROOT` substituted at call time — and never written to disk | `templates/pointer.md`, rendered into `.spectomat/pointer.md` at arm time and on every resume | the text varies only in `PLUGIN_ROOT`, which every script already holds. A rendered file adds a path for `disarm()` to clean up, a re-render on resume, and a stale `PLUGIN_ROOT` after a plugin reinstall. `pointer_prompt_test.sh` exercises it directly (§10) |
| D24 | The Stop hook runs `phase.sh` itself and ends the flow on `FINISH`, composing the closing report in bash; `FINISH` dispatches no agent | a completion promise string the session emits; a `finish` agent; latching the finished iteration in `state.json` | a promise puts the verdict's authority in the model's hands: any text carrying the string ends a flow, a tool-call-final turn strands one, and a dirty tree at finish time never reaches the janitor. No latch is needed: `FINISH` is a stable predicate, and an actuator inside the process that evaluates it fires exactly once |
| D25 | The gates are always `./.spectomat/gates.sh`, generated once by `command-run.sh` from `package.json` and edited there by the operator | gate commands as lines inside a `contract.md` fence, parsed out by the factory | a fence makes the contract both prose and executable data: it needs a parser, and one stray fence silently changes the gates. A script is the honest shape for a list of commands: `set -e` chains them, the exit code is its own, and it runs by hand. One editable file per concern — `memory.md` for the rules, `gates.sh` for the checks. The cost is one more rendered file on the floor |
| D26 | The floor is slug-major: everything of one idea lives in `.spectomat/<slug>/` for its whole life, and `ARCHIVE` finishes it by writing a `done.md` (or `blocked.md`) marker in place | stage directories (`specs/`, `plans/`, `snippets/`) and a `done/` the trail is moved into | a stage-major floor spreads one idea across four directories, and a partial move that still commits leaves a CLEAN tree the janitor never sees (§5.6). A marker cannot partially apply, and the trail stays where every task file and commit message points. The cost is that finished work stays on the floor |
| D27 | `state.json` is the entire flow state: which slugs exist and the phase of each, including the terminal phases `DONE` and `BLOCKED` with their `reason`, `finished_at` and strikes. `command-run.sh`'s intake scan is the only directory listing in the system; `done.md`/`blocked.md` are the human record that nothing reads | reconciling the floor against the state; a separate `status` field beside `phase`; deleting the markers | two authorities need a reconciler, and a phase that dies between the two writes leaves them disagreeing. A `status` field is the same problem inside one file, since the picker's candidate sets are built by phase. The markers stay as the record a human reads beside the trail, with no `jq` in between. The cost: deleting a slug dir by hand does not remove it from the accounting — the operator edits `state.json`, or cancels and re-arms |
| D28 | `log.md`'s line format is produced by one script, `scripts/log.sh <PHASE> <slug> <message>`, and every writer calls it | a template in the contract that each brief and script reproduces with its own `printf`/`date` | a format restated in every writer drifts. `log.sh` fixes the timestamp itself and is the only writer of `log.md`, so a hand-written `printf >> log.md` is simply wrong. The cost is one subprocess per log line |
| D29 | The contract's *Iteration Contract* section states only the cross-cutting rule (do exactly the phase handed, work in progress always wins) and the gate script's identity; Orient's dirty-tree/inbox check, gate timing and the commit-and-log steps live in each phase brief that runs them | the generic steps centralized in the contract, with each brief restating them in phase-specific terms | the steps are not steering an operator tunes, and every brief needs them anyway to be self-contained. A brief nobody has to leave to execute is worth the hand-checked duplication. `archive.md` has none: its Orient is `agent-archive.sh` refusing a dirty tree |
| D30 | The `IMPLEMENT` phase dispatches one `spectomat:task` agent (`agents/task.md`, sonnet) per task. The task file carries everything — scope, and in `## Context` the spec verbatim, the memory lines and the codebase facts — so the worker opens only that file, its snippets, the code and `references/gates.md`. The worker builds under TDD, runs the gates into `.spectomat/<slug>/work/task-NN.gates.log`, leaves its changes uncommitted and reports `DONE` or `FAILED`; `implement` (haiku) verifies the tree against the task's `Files` and the log, makes the one `feat` commit, records `ruling.md`/`memory.md`, and closes the task in the ledger (D31) | `IMPLEMENT` building the code itself; a report file as the return channel; a `NEEDS_CONTEXT` verdict and a re-dispatch rule; letting the worker read `memory.md` or the contract | the worker's context holds one task file and the code, and nothing orchestration needs; a cheap orchestrator pairs with a capable coder. The report is checked against `git status`, the staged file list and the gates log rather than trusted, and every git write sits with the one agent that verifies. A `FAILED` report or a failed check is the strike the phase already has, so the picker, `state.json` and `log.md` learn nothing new. The cost is one extra dispatch per task and longer task files: `PLAN` and `REVIEW` quote instead of cite |
| D31 | Each planned slug carries a `tasks.json` ledger — the task list `PLAN` writes, every task's `dependsOn` and `status`, and the `commits`/`tests`/`gates` each one closed with — written only through `scripts/tasks.sh` | a `result.md` plus a `Depends on` column in the plan overview; task counters in `state.json`; folding the ledger into `state.json`; a `tasks.json` that also replaces `state.json` | one home for facts that could otherwise disagree. Readiness is one `jq` walk (`tasks.sh next`), and the close is atomic with the phase move it earns. It holds the per-task commit range, the `REVIEW` phase's only way to rebuild the diff; `state.json` stays for the flow level. The cost is one more file per slug |
| D32 | The inbox is `.wishlist/` at the repo root, beside the floor rather than inside it | `.spectomat/drafts/`, one directory under the floor | every file on the floor is written by a phase; the inbox is written only by the operator, and no phase may touch it. Inside `.spectomat/` every rule about it is a carve-out. The cost is a second `mkdir` in `command-run.sh` and one more directory in the project root |
| D33 | `state.json` carries `current: {phase, slug}`, the last working verdict handed out, written by the Stop hook in the write that bumps `iteration` and by `arm_flow` for the first iteration. A `RECOVER` or `FINISH` verdict never replaces it, and the picker hands `current.slug` to a dirty-tree `RECOVER` | the picker writing it itself; a `RECOVER` with no slug, the janitor inferring slug and phase from the dirt | a dirty tree is an iteration that died mid-phase, and which one is known at dispatch. The hook already writes `state.json` once per iteration, so recording it costs nothing and the picker stays pure. `current` is read only for `RECOVER`'s slug and `/spectomat:status`; the next phase is always re-picked, never remembered |
| D34 | The Stop hook runs the picker once via `ask_picker`, and `pointer_prompt()` embeds that same block in the text fed back, so the dispatched session reads the verdict rather than running `phase.sh` again | the session running `phase.sh` itself as step 1 of the iteration | nothing mutates `state.json` or the tree between the two runs, so the second cannot answer differently (§3.1). Embedding drops one subprocess and one blind tool call per iteration; `ask_picker` keeps the raw block in `PICK_BLOCK` beside `PICK_PHASE`/`PICK_SLUG` |
| D35 | `implement` proves RED itself on every task that adds a test: it stashes the task's non-test Files, runs the task file's Step 2 command, pops the stash, and records `red: <command> → <summary>` in the close. The worker's DONE report carries a `Red` line as supporting detail, never as the verdict | judging test-first from the worker's report or the gates log | the gates log holds only the green run and new test files are untracked, so no artefact proves test-first. Judging the claim made the same evidence pass on one task and strike on the next: three strikes blocked a 19-task slug with every suite green. One extra test run per task makes the check deterministic |
| D36 | The floor is local: `.spectomat/.gitignore`, rendered once and committed, ignores everything but itself, `memory.md` and `gates.sh`. Only `IMPLEMENT` commits — one `feat` commit per task. `memory.md` is committed at arming when git does not know it yet and afterwards by the operator alone: no phase stages it, and `dirt()` leaves it out of `git status`. A phase that dies on the floor leaves no dirt, stays at its phase and redoes its leftovers. Arming refuses while HEAD or a `feat/*` branch still tracks another floor file | the whole floor committed, every phase making its own commit, with four runtime paths appended to the project's root `.gitignore`; the whole floor ignored, config included; `memory.md` committed by `IMPLEMENT` or by each phase that writes it | committed floor files put `chore`/`docs` commits between every `feat` commit, made `memory.md` diverge per `feat/<slug>` branch and conflict on merge, and had the plugin edit the user's root `.gitignore`. The operator's files stay tracked: they are config the team and CI share, `gates.sh` keeps D6's trust level, and `memory.md` carries the operator's Rules (D9) and outlives the working tree. Left uncommitted by the flow, its edits ride every checkout, so it never diverges between branches, and the operator reviews what the factory learned before it enters history. `state.json` already is the only authority on phase (D17, D27), so dirt is no longer needed to catch a dead doc phase. The cost: specs, plans, ledgers and markers have no git history and are lost with the working tree; a checkout that would overwrite a `memory.md` edit fails until the operator commits it; a branch still tracking a now-ignored file would silently overwrite it on checkout, hence the refusal |
| D37 | The Stop hook exits quietly — no block, no iteration bump — while its input's `background_tasks` lists a running `spectomat:*` subagent | forcing `run_in_background: false`; tracking agents with SubagentStart/SubagentStop marker files | a harness that runs every subagent in the background ends the dispatching turn at once, and feeding the pointer back then hands the session the verdict it is already working on, turn after turn. The hook input already names the running tasks, so no extra hook or marker file can go stale |
